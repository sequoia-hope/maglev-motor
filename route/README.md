# Routing the amzhex coil board

A toolchain that takes the `amzhex` preset from the simulator to a real,
autorouted `.kicad_pcb` and checks it against JLCPCB's published 12-layer
capabilities. Everything here is a thin driver around `src/kicad.js` — the board
itself is still generated by the same code the app and the tests use.

```
gen.mjs      preset  ->  amzhex.kicad_pcb        (the real 12-layer board)
route.mjs    board   ->  amzhex.route.dsn        (the routing problem, see below)
freerouting  dsn     ->  amzhex.route.ses
finish.sh    ses     ->  out/*.kicad_pcb + DRC + PNG
```

Run it:

```sh
node gen.mjs amzhex                                  # writes amzhex.kicad_pcb
node route.mjs amzhex amzhex.kicad_pcb               # writes amzhex.route.dsn
java -Xmx16g -jar freerouting-2.2.4.jar \
     -de amzhex.route.dsn -do amzhex.route.ses -mp 60
./finish.sh amzhex.kicad_pcb amzhex.route.ses amzhex-routed
```

`--tile=3` on `route.mjs` (with `SPARE=n gentile.mjs`) does the same on a 3x3
board, which is how everything here was debugged.

## Why the router does not see the real board

The full board is ~250 000 track segments of coil spiral. Handed that, freerouting
spends all its time re-deriving that none of it is routable, and one autorouter
pass on a NINE-coil tile took 86 seconds. It is also the wrong description of the
problem: the ten winding layers are not a routing resource, they are ten solid
layers of copper whose only effect on the router is that a plated THROUGH via
cannot be drilled through them.

So `mkdsn.mjs` writes the routing problem rather than the board:

* only the electronics (spare) layers exist, as signal layers;
* every coil is one hexagonal **via_keepout** — vias may not be drilled into the
  winding, which leaves exactly the gutter lattice, which is the physical truth;
* every crossover via, every terminal via and every crossover *tab* is a keepout
  too (see the notes below — each of those was learned the hard way);
* every pad is a single-pin component placed at its absolute position with its
  rotation baked into a polygon padstack, so no image/rotation/mirror convention
  can go wrong between the board and the router.

Same tile, same nets: 86 s/pass became 2 s/pass.

`mkses.mjs` merges the `.ses` back onto the FULL twelve-layer board, and that
merged board is what gets DRC'd. DRC on the proxy would prove nothing.

## Design rules

`fabRuleFiles()` in `src/kicad.js` generates the `.kicad_dru` and `.kicad_pro` that go
beside every exported board, from JLCPCB's published numbers
for FR-4 at 12 layers, 1 oz (read 2026-07-27):

| rule | value | source |
|---|---|---|
| min track / space | 0.09 / 0.09 mm | "1oz: 0.09/0.09mm (3.5/3.5 mil) for multi-layer" |
| min via hole / diameter | 0.15 / 0.25 mm | "Min. Via hole size/diameter" |
| min annular ring | 0.13 mm | JLCPCB support answer 110 |
| via hole-to-hole | 0.2 mm | "Via Hole-to-Hole Spacing" |
| copper to routed edge | 0.2 mm | "Copper clearance from routed board edges" |
| hole to copper | 0.2 mm | "Inner layer via hole to copper" |

They come out of the same `FAB` object the geometry is sized from, so the thing
being checked and the thing being drawn cannot drift.
The board is drawn with 0.5 mm vias on 0.2 mm drills (a 0.15 mm ring), which
clears every floor above with margin.

## Things that were wrong with the board, and are not now

Each of these was found by putting the board through this pipeline. Two of them
are shorts that **no PCB design-rule check can report**, because both halves of
the short are the coil's own net.

1. **Duplicate reference designators.** The dead-man's hold capacitor was `C1`,
   the same as coil 1's decoupling cap. KiCad's Specctra exporter keys its
   component list by reference and simply refuses to write the file — the board
   could not reach an autorouter at all. (`emitDeadman`, now `CDM1`/`RDM1`/etc.)

2. **A via no fab will drill.** The via was `min(0.4, max(0.2, pitch*0.6))`, a
   formula with no fab behind it, which came out 0.2 mm on a 0.1 mm drill and
   broke three JLCPCB rules at once — diameter, drill and annular ring. It is
   now derived from `FAB` and from the gutter the coil fill leaves
   (`viaSize`, `gutterFits`).

3. **A coil fill too greedy to host that via.** 84% fill leaves 0.59 mm of
   gutter; a legal via needs 0.79 mm (clearance in, via, edge clearance out).
   amzhex is now 80%, which costs *no* winding at all — turns-per-layer is
   `floor()`-quantised and comes out 12 either way.

4. **Odd winding-layer counts short every coil.** A spiral alternates which end
   it finishes on: layer 0 starts outside, layer 1 starts inside, and so on. With
   an ODD winding count the last layer ends in the CENTRE HOLE, and the tab that
   carries that lead out to its I/O pad crosses every turn of its own layer — a
   dead short of the whole layer, on all 168 coils. `pcbSpareLayers: 1`
   guarantees it. amzhex is now `2`. `validatePcb` checks it and
   `buildKiCad().stats.sameNetShorts` reports it.

5. **Via lands touching.** With a fab-sized via the five inner crossover vias
   nearly overlap in the centre hole. Same net, so DRC says nothing — but two
   touching lands weld the layer c/c+1 crossover to the c+2/c+3 one and short two
   whole layers out of the series stack. Now spread on a ring, and checked.

6. **`((a - b + PI) % 2PI) - PI`.** JS `%` is a remainder and keeps its sign, so
   this "smallest angle between two directions" returned garbage for half its
   inputs. It picked the hexagon flat 83 degrees away from a winding end, and the
   5.2 mm tangential tab that produced swept across the gutter and shorted a
   routed net to a coil. Now `atan2(sin(a-b), cos(a-b))`.

7. **A register placed on top of other parts.** The register search gave up after
   two cells and emitted the part on its target anyway; on the full board that
   put SR40's pads through U162's — six shorted nets. It now escalates its search
   radius the way the service parts always did.

8. **Both coil ends carried one net.** The winding is continuous copper, so its
   two terminals genuinely ARE one net and KiCad is right to say so — but the
   bridge's two outputs were given that same net, and a router reads the netlist,
   not the physics. Told that four pads are one net it satisfied it the cheap
   way: a wire straight from OUTA to OUTB. Every bridge output shorted, every
   coil bypassed, and the result reported as routed. The router is now handed
   the coil as a two-terminal COMPONENT (`coil_i_A` / `coil_i_B`, split in
   `route.mjs`) with the winding absent from its netlist; the pairing is the
   fixed convention `BRIDGE_OUT_PADS` records, so IN1 high always means current
   IN→OUT and the commutation signs mean the same thing on every cell.

9. **The bridge's exposed pad could not be connected to anything.** Chasing why
   GND kept failing turned up ratsnest entries reading *U1 ↔ U1*: the package's
   own power pads could not reach each other. A WSON/DFN die pad is an island —
   0.1 mm to all eight perimeter pads, which no legal trace fits through — and
   the usual escape, a via in the pad, is unavailable here because the part sits
   over winding copper, where a plated through hole would short the coil. The
   bridge is now a **SOT-23-6**: six perimeter pins is exactly an H-bridge's pin
   count, 0.95 mm pitch leaves 0.35 mm between pads (a 0.1 mm trace with
   clearance either side), and every pin is reachable. Packages with a
   `padIsland` now carry a large penalty in the fit search, because "fits best"
   and "can be wired" are different questions and the second one decides.

Plus, on the router side: pads were being mirrored (rotation applied in the
y-down frame and then y-flipped), which made every net touching a 30-degree
register unroutable; keepouts have to be grown by a clearance because
freerouting does not apply the clearance rule to them; and terminal vias need
keepouts on the inner electronics layers even though their B.Cu land is a pad.

## The stack: 12 + 2, not 12

The electronics layers are ADDED to the twelve winding layers rather than taken
out of them, so the board is 14 copper layers. Both halves matter:

* they must come in a **pair**, because an odd winding count strands a coil lead
  in the centre hole (finding 4 above);
* they must be **added**, because taking two out of twelve costs a fifth of the
  winding — 120 turns instead of 144 — and buys no routing improvement at all
  (measured on the 3x3 tile: 12+2 and 14+2 both plateau within two connections
  of each other).

The price is a 14-layer stack, which is past the layer count where PCB pricing
turns steep, and a wider via drill: 1.84 mm of board through a 0.2 mm hole is a
9:1 plated hole and the fab does 8:1, so `minDrillFor()` opens it to 0.23 mm and
the ring comes down to 0.135 mm — still over the 0.13 mm floor.

## Known remaining

* **GND and VBUS want to be planes, not nets.** 749 and 505 pads respectively.
  `PLANES=GND,VBUS` keeps them out of the router's netlist for experiments; a
  real build should surrender two more layers to a GND and a VBUS pour (which
  keeps the winding count even, so parity stays satisfied) and let the router
  have only the signals.
* **Freerouting plateaus at roughly half the board, and nothing moves it.**
  It converges and then stops -- a 150-pass run on the 3x3 tile finished in the
  same 2 minutes and at the same 44 unrouted as a 30-pass one. Everything tried,
  measured on that tile (unrouted connections, lower is better):

  | change | result |
  |---|---|
  | 2 electronics layers | 42-44 |
  | 4 electronics layers | 44 |
  | 6 electronics layers | 44 |
  | 30 passes vs 150 passes | identical |
  | register quads: 4-in-a-row vs 2x2 block | 44 -> 42 |
  | GND/VBUS routed vs excluded (i.e. poured) | 37 vs 34 signal connections |
  | local nets pre-laid as fixed wiring | 5x slower, no further |

  **A trap worth knowing:** freerouting 2.2.4 silently IGNORES a
  `freerouting.json` in the working directory. Setting `max_passes: 1` there
  runs 24 passes; the same setting as `FREEROUTING__ROUTER__MAX_PASSES=1` runs
  one. Every router setting has to go through those `FREEROUTING__`-prefixed
  environment variables (double underscore per level of nesting), and until
  that was found none of the tuning above was reaching the router at all. With
  it reaching the router, `VIA_COSTS=10 START_RIPUP_COSTS=1000` is the best
  combination found -- worth 42 -> 38, and it does change behaviour (via count
  goes 17 -> 29 as the cost drops), but it does not change the conclusion.

  Later measurements, same tile, through-hole vias only:

  | change | result |
  |---|---|
  | gutter vias per cell 7 -> 4 (fewer winding layers) | 38 -> 37 |
  | coil fill 0.80 -> 0.74 -> 0.68 (wider gutter, smaller coil) | 38 -> 40 -> 38 |
  | coil centre hole enlarged (144 -> 132 -> 108 turns) | 45 -> 46 -> 43 |
  | **blind vias between the two electronics layers** | **38 -> 5** |

  The full 168-coil board does NOT converge the way the tile does -- it keeps
  gaining: 1245, 1193, 1125, 1073, 1002, 933, 877, 835, 778, 771, 710 unrouted
  over eleven passes. Note the tenth pass (778 -> 771, a gain of 7) followed by
  the eleventh (771 -> 710, a gain of 61): a single slow pass is NOT convergence
  on this board, and reading it as one is a mistake worth not repeating. Hence
  grind.sh, which keeps going in rounds and carries each round's result forward
  rather than stopping at a fixed pass count.

  So it is not the gutter being crowded (halving its via count moved one
  connection), not the gutter being narrow (a wider one costing 12 turns moved
  nothing), and not the coil's centre hole (36 turns bought nothing). The only
  thing that moves it is where a via may be PLACED. With plated through-holes a
  via can only go where no winding layer has copper -- the gutter lattice, plus
  a centre hole too small to use -- so inside a cell, under the parts, B.Cu is
  the only layer a trace can reach. That is why extra electronics layers are
  worthless: they are all equally unreachable. Allow a blind via between the two
  electronics layers, which never enters the winding, and the same tile goes
  from 38 unrouted to 5 (19 vias placed becomes 116). That is a fabrication
  decision, not a layout one.

  More layers do not help; more passes do not help; taking the power nets out
  does not help the signals. What IS routed comes back DRC-clean every time, so
  this is the router giving up rather than the board being full -- the rendered
  result still has a lot of empty copper. A different autorouter, or a
  purpose-built one that exploits the lattice's periodicity, is the next thing
  to try.
* **The square-grid presets (`pcb`, `pcbmini`, `pcb2oz`) are still at 0.94 fill**,
  which leaves 0.24 mm of gutter — not enough for a fab-legal via. They export,
  and `gutterFits()` reports the shortfall, but their vias are pinned against the
  winding. Fixing them means the same fill reduction, which for them *does* cost
  turns (13 -> 11), so it is a design decision rather than a bug fix.
